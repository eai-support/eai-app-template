# Issue #3503: authenticated generated-app build evidence

## Approval and scope

The owner approved this hardening scope on 2026-09-25. It covers reviewed provenance, identity, compatibility, credential-safety, and workflow fixes while preserving both successful source-mode journeys. It does not authorize merge, release, deployment, activation, billing, or destructive live tests.

Canonical amendment: https://github.com/enterpriseaigroup/Issues2025/issues/3503#issuecomment-5826177803

## Preserved user contract

- The workflow supports both `source-unknown` and `eai-cli-generated` sources.
- Existing callers using the prior `environment` input remain compatible while `env` is supported.
- Exact commit build and evidence submission remain the workflow outcome.
- No long-lived EAI, GitHub App, Azure, or platform credential is exposed to application scripts.

## Requirements

- **DTE-018:** hash all governed configuration source and runtime provenance inputs, including nested `.test.*` and `.spec.*` files and the deployment contract; exclude only the two deterministic generated Object Type outputs, reject live and dangling links in every governed path component plus every nonregular filesystem entry, bind device, inode, size, modification time, and change time from the pre-open snapshot through the opened descriptor and post-read path, repeat the governed inventory to reject additions or removals, and accept the canonical base-template, approved-source, or approved-release provenance anchors without an unbound fixture fallback.
- **DTE-019 through DTE-021:** expose a canonical workflow/collector pair, declare all dispatch inputs, preserve explicitly empty optional aliases, and reject malformed operation/path values before URL construction. Evidence reports observed lowercase 40-hex Git `workflowBlobSha` and algorithm-qualified `collectorDigest` values from the exact source commit; the platform independently fetches, verifies, and seals the authoritative values through the linked installation before accepting OIDC handoff. Apply the generated-runtime app-key grammar at every validation stage and retain every deployment environment supported by the template contract, including `demo`.
- **DTE-022:** explicitly upload the hidden build artifact, prove it is a nonempty no-follow regular file with size and digest evidence, and create the image context, archive metadata, and evidence output only through confined no-link directory trees without replacing an existing evidence file. Before upload, copy the built archive through bounded no-follow source and exclusive destination descriptors into a cryptographically random runner-temporary staging directory, emit its exact path and digest, and upload only that staged file. Bind every source/output parent and opened leaf identity through each read or write. Create generated image-context files exclusively without truncating a preexisting path. Copy standalone, static, and public trees entry by entry without following nested links or accepting nonregular files; snapshot and revalidate each source file's complete ancestor chain and final contained path before and after copying. Fail closed on preexisting isolated outputs instead of deleting through mutable paths, and leave a failed bound-copy output in place for the disposable job workspace rather than performing an unsafe error-path unlink.
- **DTE-023:** pin actions and base images to immutable commits or digests.
- **DTE-024:** emit a standard artifact provenance attestation where the repository/action capability supports it.
- **DTE-025:** run application-controlled install/build/test work in a job without OIDC authority, verify post-build source integrity, and perform attestation and handoff in a separate job that receives only immutable artifacts and exact dispatch inputs. Revalidate the complete downloaded evidence contract, artifact metadata, OCI image digest, workflow/run identity, canonical source-provenance shape and anchors, canonical workflow blob, and collector digest before requesting OIDC. Independently fetch the exact commit tree and governed blobs with bounded concurrency, recompute the canonical configuration manifest, and compare it with dispatch and evidence hashes. Every collector read snapshots and revalidates its complete parent chain and opened leaf before and after reading. Never select the endpoint from a mutable secret, persist credentials into app-visible files, allow provenance values to inject additional GitHub outputs, or follow a replaced `$GITHUB_OUTPUT` command-file leaf or ancestor when publishing collector outputs. Revalidate the exact command-file descriptor, leaf path, and complete parent chain after the append and before the step returns. Keep the minted OIDC token within the submission step; never append it to a mutable GitHub command file.
- **DTE-026:** preserve existing workflow inputs additively and test conflict/precedence behavior.
- **DTE-036, DTE-074:** bind an authenticated readiness success to the exact active deployment as well as tenant, app, environment, and configuration. Require server-only runtime `EAI_DEPLOYMENT_ID` and an equal `X-EAI-Deployment-Id` probe header. Missing runtime identity is incomplete configuration; a missing or unequal header is `tenant_assignment_invalid`. Preserve the existing response schema and leave durable operation/source doctor authority to TenantInfra.
- **DTE-086 through DTE-088:** integrate current `main`, rerun owned checks, and defer the release tag/commit until the producer is actually released.

## Acceptance

1. Both source modes validate operation, nonce, canonical app key, tenant, every template-supported environment, workflow, ref, and commit before composing an evidence URL. `eai-cli-generated` requires and validates the exact target tenant; the legacy `source-unknown` contract validates it when supplied without making the compatibility input mandatory. Explicitly empty optional aliases remain empty and do not become boolean flags.
2. Configuration and provenance hashes change for every governed source input, including `.test.*` and `.spec.*` files, remain stable only across the two deterministic generated Object Type outputs, and reject dangling or live symlinks in a governed entry or any ancestor plus FIFOs, sockets, devices, and other nonregular entries.
3. Runtime provenance preserves and validates any canonical approved source anchor in both the collector and the isolated OIDC-authorized handoff; matching malformed values never pass by equality alone.
4. Hidden OCI artifacts upload with a nonzero size and digest; EAI evidence and standard attestation identify the same subject. Image-context preparation, archive inspection, metadata, and evidence creation reject a linked or non-directory ancestor, linked or existing evidence files, paths outside the application root, and links or nonregular entries nested in standalone, static, or public source trees, including an application-controlled `.eai-build` replacement after the build.
5. Existing `environment` callers and new `env` callers work; conflicting values fail.
6. All third-party workflow actions and the OCI base image use immutable identities.
7. Application lifecycle code cannot request the handoff OIDC token or change the validated endpoint; a post-build integrity check rejects source mutation before evidence collection, the handoff rejects evidence with a different nonce before requesting OIDC, every value appended to `$GITHUB_OUTPUT` is a single safe line written through a no-follow regular-file descriptor whose exact leaf and ancestors are revalidated after the append, and the OIDC token stays inside the request-and-submit step without a GitHub command-file write.
8. Evidence and handoff bind the exact source commit's canonical workflow Git blob SHA and collector SHA-256 digest, and the isolated handoff independently revalidates every submitted identity, digest, run, source, and provenance field before token issuance.
9. Owned validation and evidence-collector tests pass on current `main`.
10. The handoff independently computes `configHash` from the exact commit tree and governed Git blobs before OIDC, and rejects a missing, linked, nonregular, truncated, oversized, or substituted manifest entry.
11. Generated Dockerfile and evidence writes reject an ancestor or leaf replacement before bytes leave the bound descriptor, create new files exclusively without truncating a preexisting inode, and revalidate both after writing.
12. Collector reads reject an ancestor, leaf, size, or inode replacement during the read, and the isolated handoff fetches at most eight governed Git blobs concurrently while preserving sorted manifest order.
13. Image preparation rejects preexisting context, static, public, archive, or metadata outputs; a copy failure never performs path-based cleanup after parent validation fails.
14. Configuration hashing repeats the sorted governed inventory and binds parent, contained path, leaf, size, modification time, and change time from the pre-open snapshot through every opened descriptor and completed read.
15. Image-tree copying rejects a source ancestor or final-path replacement before copied bytes are accepted, and revalidates the opened source inode and complete parent chain after the copy.
16. Artifact upload consumes only the random runner-temporary file created by a bounded no-follow staging copy after the build; its raw archive digest remains bound through evidence and isolated handoff verification.
17. Readiness returns success only when the authenticated TenantInfra probe supplies the exact active deployment ID. A missing runtime deployment ID fails configuration readiness, while missing or changed deployment headers return 403 `tenant_assignment_invalid` without changing the successful payload.
