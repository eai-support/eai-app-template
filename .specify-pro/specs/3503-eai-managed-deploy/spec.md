# Issue #3503: authenticated generated-app build evidence

## Approval and scope

The owner approved this hardening scope on 2026-09-25. It covers reviewed provenance, identity, compatibility, credential-safety, and workflow fixes while preserving both successful source-mode journeys. It does not authorize merge, release, deployment, activation, billing, or destructive live tests.

Canonical amendment: https://github.com/enterpriseaigroup/Issues2025/issues/3503#issuecomment-5826177803

## Preserved user contract

- The workflow supports both `source-unknown` and `eai-cli-generated` sources.
- Existing callers using the prior `environment` input remain compatible while `env` is supported.
- Exact commit build and evidence submission remain the workflow outcome.
- No long-lived EAI, GitHub App, Azure, or platform credential is exposed to application scripts.

## Requirements

- **DTE-018:** hash all governed configuration source and runtime provenance inputs, including nested `.test.*` and `.spec.*` files and the deployment contract; exclude only the two deterministic generated Object Type outputs, reject live and dangling links in every governed path component plus every nonregular filesystem entry, enforce the same 10 MiB per-file, 32 MiB total, and 4,096-file manifest limits in collector and isolated handoff, read only through a fixed-size descriptor loop bounded by the opened snapshot, bind device, inode, size, modification time, and change time from the pre-open snapshot through the opened descriptor and post-read path, repeat the governed inventory to reject additions or removals, and accept the canonical base-template, approved-source, or approved-release provenance anchors without an unbound fixture fallback. Keep the local `config-hash` command usable on Windows, where Node does not expose `O_NOFOLLOW` or `O_NONBLOCK`, through an explicit read-only Windows fallback that retains the complete ancestor, contained-path, pre-open leaf, opened descriptor, rebound path, and post-read identity checks. Never enable that fallback for deployment commands.
- **DTE-019 through DTE-021:** expose a canonical workflow/collector pair, declare all dispatch inputs, preserve explicitly empty optional aliases, and reject malformed operation/path values before URL construction. Evidence reports observed lowercase 40-hex Git `workflowBlobSha` and algorithm-qualified `collectorDigest` values from the exact source commit; the platform independently fetches, verifies, and seals the authoritative values through the linked installation before accepting OIDC handoff. Apply the generated-runtime app-key grammar at every validation stage and retain every deployment environment supported by the template contract, including `demo`.
- **DTE-022:** explicitly upload the hidden build artifact, prove it is a nonempty no-follow regular file with size and digest evidence, and create the image context, archive metadata, and evidence output only through confined no-link directory trees without replacing an existing evidence file. Before upload, copy the built archive through bounded no-follow source and exclusive destination descriptors into a cryptographically random runner-temporary staging directory, emit its exact path and digest, and upload only that staged file. Bind every source/output parent and opened leaf identity through each read or write, including size, modification time, and change time between the source pre-open snapshot, opened descriptor, rebound path, and final path. Create generated image-context files exclusively without truncating a preexisting path. Copy standalone, static, and public trees entry by entry without following nested links or accepting nonregular files; snapshot and revalidate each source file's complete ancestor chain and final contained path before and after copying. Every collector open that claims no-follow semantics must use a shared fail-closed capability check; an unavailable or zero `O_NOFOLLOW` flag is an error and never degrades to a link-following open. Fail closed on preexisting isolated outputs instead of deleting through mutable paths, and leave a failed bound-copy output in place for the disposable job workspace rather than performing an unsafe error-path unlink.
- **DTE-023:** pin actions and base images to immutable commits or digests.
- **DTE-024:** emit a standard artifact provenance attestation where the repository/action capability supports it.
- **DTE-025:** run application-controlled install/build/test work in a job without OIDC authority, verify post-build source integrity, and perform attestation and handoff in a separate job that receives only immutable artifacts and exact dispatch inputs. Revalidate the complete downloaded evidence contract, artifact metadata, OCI image digest, workflow/run identity, canonical source-provenance shape and anchors, canonical workflow blob, and collector digest before requesting OIDC. Hash both the collector's staged archive and the isolated handoff's downloaded archive through fixed-size no-follow buffers, enforce the declared 10 GiB bound before and through each read, stop at the opened size, probe one byte past it to reject growth, and revalidate the opened regular-file identity instead of loading the complete artifact into memory or streaming to an unbounded EOF. Treat the archive index digest as an untrusted pointer: require an OCI layout marker and one canonical lowercase SHA-256 Linux/amd64 descriptor, extract only its exact `blobs/sha256/<hex>` entry through a bounded subprocess stream, hash the extracted manifest bytes, and require that computed digest to match both the index descriptor and build evidence before requesting OIDC. Require the bound image manifest to contain one valid bounded OCI or Docker configuration descriptor and a bounded array of valid matching-family layer descriptors. In one bounded archive pass, stream each unique referenced configuration/layer blob through a fixed validator, require one regular member with the descriptor's exact path and size, and hash its bytes to the descriptor digest. Count a separate verbose archive record as well as one validator record for every expected member so a same-name nonregular duplicate cannot be ignored. Carry the expected descriptors in a compact bounded table that stays below Linux's per-environment-string limit at the full accepted layer count. Reject missing, duplicate, mixed-type, mixed-family, malformed, oversized, excessive, or substituted descriptors and blobs even when the manifest bytes match the expected digest. Read downloaded evidence through a 1 MiB no-follow descriptor snapshot, and stream every exact-source or GitHub metadata response through a path-specific byte cap before JSON parsing or retention: 1 MiB for producer sources and ordinary metadata, 10 MiB for the governed runtime, and 16 MiB for recursive tree and base64 blob responses. Independently fetch the exact commit tree and governed blobs with bounded concurrency, recompute the canonical configuration manifest, and compare it with dispatch and evidence hashes. Every collector read uses a fixed-size descriptor loop with an explicit per-file cap, rejects growth beyond the opened snapshot, and revalidates its complete parent chain and opened leaf before and after reading. Cap both the OIDC token response and PublicAPI handoff response transfer at 1 MiB from the actual byte stream, including responses without a usable `Content-Length`, then parse the handoff response with trusted inline bounded no-follow code; never check out or execute repository code in the OIDC-authorized job. Keep the collector's standalone response parser subject to the same bounds. Never select the endpoint from a mutable secret, persist credentials into app-visible files, allow provenance values to inject additional GitHub outputs, or follow a replaced `$GITHUB_OUTPUT` command-file leaf or ancestor when publishing collector outputs. Revalidate the exact command-file descriptor, leaf path, and complete parent chain after the append and before the step returns. Keep the minted OIDC token within the submission step; never append it to a mutable GitHub command file. Reject any workflow invocation whose caller event is not `workflow_dispatch` before checkout or application-controlled work.
- **DTE-026:** preserve existing workflow inputs additively and test conflict/precedence behavior. Keep `config_hash` required for direct `workflow_dispatch`; keep it optional for the historical `workflow_call` schema, derive it from the exact checked-out governed configuration when omitted, and require an explicitly supplied value to match that same digest before application work. Preserve `workflow_call` only for a manually dispatched caller in the same repository and at the same ref as the canonical callee. PublicAPI must verify the signed OIDC caller `workflow_ref` and complete callee `job_workflow_ref`/`job_workflow_sha` pair, require the canonical `.github/workflows/eai-app.yml` callee path, and exact-bind both refs plus the lowercase 40-hex job/source SHA. Reject partial reusable claims, cross-repository or cross-ref calls, unsafe workflow paths, and reusable claims on a direct dispatch. The called workflow must not restore the deprecated long-lived EAI token path, and its caller must grant the declared contents, packages, actions, attestation, and OIDC permissions because a called workflow cannot elevate caller permissions.
- **DTE-036, DTE-074:** bind an authenticated readiness success to the exact active deployment as well as tenant, app, environment, and configuration. Require server-only runtime `EAI_DEPLOYMENT_ID` and an equal `X-EAI-Deployment-Id` probe header. Missing runtime identity is incomplete configuration; a missing or unequal header is `tenant_assignment_invalid`. Preserve the existing response schema and leave durable operation/source doctor authority to TenantInfra.
- **DTE-086 through DTE-088:** integrate current `main`, rerun owned checks, and defer the release tag/commit until the producer is actually released.

## Acceptance

1. Both source modes validate operation, nonce, canonical app key, tenant, every template-supported environment, workflow, ref, and commit before composing an evidence URL. `eai-cli-generated` requires and validates the exact target tenant; the legacy `source-unknown` contract validates it when supplied without making the compatibility input mandatory. Explicitly empty optional aliases remain empty and do not become boolean flags.
2. Configuration and provenance hashes change for every governed source input, including `.test.*` and `.spec.*` files, remain stable only across the two deterministic generated Object Type outputs, and reject dangling or live symlinks in a governed entry or any ancestor plus FIFOs, sockets, devices, and other nonregular entries.
3. Runtime provenance preserves and validates any canonical approved source anchor in both the collector and the isolated OIDC-authorized handoff; matching malformed values never pass by equality alone.
4. Hidden OCI artifacts upload with a nonzero size and digest; EAI evidence and standard attestation identify the same subject. Image-context preparation, archive inspection, metadata, and evidence creation reject a linked or non-directory ancestor, linked or existing evidence files, paths outside the application root, and links or nonregular entries nested in standalone, static, or public source trees, including an application-controlled `.eai-build` replacement after the build.
5. Existing `environment` callers and new `env` callers work; conflicting values fail.
6. All third-party workflow actions and the OCI base image use immutable identities.
7. Application lifecycle code cannot request the handoff OIDC token or change the validated endpoint; a post-build integrity check rejects source mutation before evidence collection, the handoff rejects evidence with a different nonce before requesting OIDC, every value appended to `$GITHUB_OUTPUT` is a single safe line written through a no-follow regular-file descriptor whose exact leaf and ancestors are revalidated after the append, and the OIDC token stays inside the request-and-submit step without a GitHub command-file write.
8. Evidence and handoff bind the exact source commit's canonical workflow Git blob SHA and collector SHA-256 digest, and the isolated handoff independently revalidates every submitted identity, digest, run, source, and provenance field before token issuance.
9. Owned validation and evidence-collector tests pass on current `main`.
10. The handoff independently computes `configHash` from the exact commit tree and governed Git blobs before OIDC, and rejects a missing, linked, nonregular, truncated, oversized, or substituted manifest entry.
11. Generated Dockerfile and evidence writes reject an ancestor or leaf replacement before bytes leave the bound descriptor, create new files exclusively without truncating a preexisting inode, and revalidate both after writing.
12. Collector reads use fixed-size capped descriptor loops and reject file growth plus any ancestor, leaf, size, or inode replacement during the read; the isolated handoff fetches at most eight governed Git blobs concurrently while preserving sorted manifest order.
13. Image preparation rejects preexisting context, static, public, archive, or metadata outputs; a copy failure never performs path-based cleanup after parent validation fails.
14. Configuration hashing repeats the sorted governed inventory and binds parent, contained path, leaf, size, modification time, and change time from the pre-open snapshot through every opened descriptor and completed read.
15. Image-tree copying rejects a source ancestor or final-path replacement before copied bytes are accepted, and revalidates the opened source inode and complete parent chain after the copy.
16. Artifact upload consumes only the random runner-temporary file created by a bounded no-follow staging copy after the build; its raw archive digest remains bound through evidence and isolated handoff verification.
17. Readiness returns success only when the authenticated TenantInfra probe supplies the exact active deployment ID. A missing runtime deployment ID fails configuration readiness, while missing or changed deployment headers return 403 `tenant_assignment_invalid` without changing the successful payload.
18. Direct CLI dispatch remains unchanged and still requires its server-issued `config_hash`. A reusable invocation can retain the historical input set without `config_hash`: the workflow derives the exact checked-out configuration digest before application work, while any supplied digest must match. It proceeds only from a `workflow_dispatch` caller and succeeds only when PublicAPI verifies a complete signed caller/callee claim set for the same repository, ref, canonical callee path, and source SHA. Missing, partial, malformed, cross-repository, cross-ref, or direct-call job claims fail without a legacy token fallback.
19. The isolated handoff computes the downloaded OCI archive digest with a fixed-size buffer through a no-follow regular-file descriptor, rejects an empty, oversized, linked, or changing archive, and never allocates memory proportional to the permitted 10 GiB artifact size.
20. Every generated-tree and staged-archive copy rejects a same-inode, same-size pre-open rewrite through exact modification/change-time binding, and both configuration hash implementations accept files through 10 MiB while enforcing the same 32 MiB total and 4,096-file manifest limits.
21. The collector's staged-archive digest reads only the opened size through a fixed buffer, rejects premature EOF, probes one byte beyond the bound to reject growth, and contains no unbounded file stream or descriptor-wide read.
22. The handoff transfer rejects a response above 1 MiB, and trusted inline status parsing in the clean handoff job rejects a linked, oversized, growing, replaced, or nonregular response file without checking out repository code. The collector's standalone parser applies the same response-file constraints.
23. The isolated handoff rejects linked, changing, or oversized downloaded evidence before parsing it, bounds every GitHub exact-source and metadata response before parsing or retaining bytes, and caps the actual OIDC token response stream at 1 MiB even when the endpoint omits `Content-Length`, without reducing the accepted 10 MiB governed-file limit.
24. The isolated handoff accepts an OCI image digest only after validating the OCI layout marker, hashing the bounded bytes of the exact manifest blob referenced by the single Linux/amd64 index descriptor, validating its bounded configuration and layer descriptors, and streaming each unique referenced blob once to verify its regular-file type, exact path, size, and digest. Separate member and verified-record counts reject mixed-type duplicates, a compact expected-descriptor table remains below the Linux per-string execution bound at 1,024 layers, and the validator output cap is derived to accept the full configuration-plus-layer record set while rejecting any extra record. A missing, malformed, mixed-family, mixed-type duplicate, excessive, oversized, truncated, or digest-substituted manifest or referenced blob fails before OIDC.
25. Every deployment collector open that depends on no-follow semantics uses one shared capability guard and fails before opening the path when a nonzero numeric `O_NOFOLLOW` flag is unavailable; no deployment read, copy, create, staging, evidence, or GitHub command-file path silently follows links. The local-only `config-hash` command may use the explicit Windows read fallback only on `win32`, while retaining complete ancestor, containment, descriptor, path, size, timestamp, and inventory binding and rejecting links or reparse points.
